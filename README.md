# Dota Replay Analyzer

Веб-приложение для загрузки и базового разбора повторов Dota 2 с помощью `gem-dota`.

## Что изменено

- Анализ выполняется как фоновая задача: браузер больше не ждёт завершения всего разбора в одном HTTP-запросе.
- Интерфейс опрашивает `/api/tasks/<task_id>` и показывает текущий этап.
- Парсер запускается в отдельном процессе, чтобы его аварийное завершение было легче диагностировать.
- Добавлен `/health` для проверки доступности приложения.
- Ошибки загрузки и разбора отображаются отдельно.

> Важно: фоновые задачи хранятся в памяти одного процесса. Для текущего развёртывания оставь **один Gunicorn worker**. Если Render перезапустится во время анализа, текущая задача потеряется. Бесплатный тариф также может не иметь достаточно RAM для некоторых больших реплеев.

## Загрузка на GitHub

1. Распакуй архив.
2. Загрузи **содержимое папки архива в корень репозитория**, сохранив структуру `app.py`, `static/`, `templates/`, `requirements.txt`.
3. Сделай commit в ветку `main`.
4. Если Render подключён к этому репозиторию, дождись автоматического деплоя.

## Настройки Render

- Runtime: Python 3
- Build Command: `pip install -r requirements.txt`
- Start Command: `gunicorn app:app --bind 0.0.0.0:$PORT --timeout 120 --workers 1 --threads 4`

Не увеличивай тайм-аут до 650 секунд: endpoint создания задачи должен быстро возвращать `202`, а фронтенд затем опрашивает состояние задачи.

## Локальный запуск на Windows

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

Открой `http://127.0.0.1:5000`.

## API

- `GET /health` — проверка приложения.
- `POST /api/analyze` — создать задачу; ответ содержит `task_id`.
- `GET /api/tasks/<task_id>` — статус задачи и, по завершении, результат.

Загрузка реплеев и автоматическое получение через OpenDota зависят от доступности источника и совместимости версии `gem-dota`.
